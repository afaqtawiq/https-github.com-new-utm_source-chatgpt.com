# ملف حي لكل شحنة — تجربة (قراءة فقط)

مبني على الموجود: `shipment_files` (ملف لكل بوليصة) + `fasah_status` وقراءات جهاز العمل (`runner_tasks`) + `shipment_tracks` + `container_returns` (مع `free_until_estimated`) + `staff_documents` (مستندات واتساب). الكود: `app/shipment_live.py`.

- البطاقة: آخر حالة **موثّقة** مع مصدرها ووقتها، الموقف، المسؤول عن الخطوة الجاية وموعدها.
- حالة فسح تُعرض كحالة حالية فقط إذا ظهرت في قراءة خلال 6 ساعات. غير ذلك تُعرض «آخر حالة معروفة» مع وقتها، والسبب واحد من اثنين:
  - «غاب عن قراءة كاملة تشمل نطاقه»: فقط إذا وُجدت قراءة لاحقة ناجحة **وكاملة** (وصلت لتاريخ النافذة أو آخر صفحة)، لنفس القائمة (استيراد/تصدير)، ونافذتها تشمل تاريخ البيان، وبدون فلتر مستورد آخر.
  - «تعذر التحقق»: إذا ما فيه قراءة بهذي الشروط (قراءة شحنات مستورد آخر، أو قراءة وقفت عند حد الصفحات، أو قراءة بدون إثبات تغطية).
  - جهاز العمل صار يرسل إثبات التغطية مع كل قراءة (`coverage`: complete / end / since / which / party).
- ربط مستند واتساب: فقط إذا **كل** المراجع الموجودة فيه (بوليصة/بيان/حاوية) تطابق نفس الشحنة. مرجع مجهول، أو مراجع متعارضة، أو اسم العميل فقط → قائمة مراجعة بدون دمج.
- الربط القديم بالاسم (`shipment_workflow.note_document`) له مفتاح `DOC_LINK_BY_NAME`؛ الإنتاج بدون تغيير (=1)، والتجربة تختبر إيقافه (=0) بدون المساس بالروابط القديمة.
- تنبيه داخلي لآخر يوم مجاني: فقط إذا التاريخ موثّق (ليس تقديريًا)، قبل يومين وحتى التأخر.
- لا إرسال واتساب، لا ترحيل مالي، لا تعديل على السجلات الموجودة (الكتابة فقط في جدولي التجربة `shipment_live_links` و`shipment_live_review`).
- صفحة الموظف `/shipment-live` تعمل فقط مع `SHIPMENT_LIVE_PILOT=1`. أداة واتساب للأقسام: `shipment_live`.
- الاختبار: `tests/shipment_live_acceptance.py` على 10 حالات تخليص منزوعة الهوية من ميناء جدة الإسلامي (`tests/fixtures/shipment_live_jeddah10.py`).
